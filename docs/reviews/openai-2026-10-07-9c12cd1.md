Major, lib/redmine_reporter_dashboards/liquid/drops/todo_list_drop.rb:34
The last_updated accessor calls list.last_updated, which is not a standard column on ActiveRecord models (Redmine/rails convention is updated_on or updated_at). In redmine_issue_todo_lists2 the model is highly likely to expose updated_at/updated_on rather than a last_updated method. A real template using {{ list.last_updated }} (advertised in drop-reference) will raise NoMethodError and fail the render when the plugin is installed.
Concrete failure: On Redmine 7 with redmine_issue_todo_lists2 installed, add {{ issue.todolists_with_positions.first.last_updated }} to a report. Rendering raises undefined method 'last_updated' for IssueTodoList:Class (or for an instance), aborting the report.
Fix: Map to the model’s real timestamp, falling back safely:
  def last_updated
    ts = if list.respond_to?(:last_updated) then list.last_updated
         elsif list.respond_to?(:updated_at) then list.updated_at
         else list.respond_to?(:updated_on) ? list.updated_on : nil
         end
    in_actor_zone(ts)
  end

Resolution: not changed, the finding is refuted. `last_updated` is a real column of `issue_todo_lists` (redmine_issue_todo_lists2 `db/migrate/001_create_todo_lists.rb:9`, stamped by `IssueTodoList#force_updated`), and it is the name the todo plugin's own RedmineUP drop used. Proven on the database by the new `test_last_updated_is_the_lists_own_timestamp` (with the todo plugin, 11 runs, 0 failures).
